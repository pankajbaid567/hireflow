# HireFlow milestone audit

Audit date: **23 October 2026 (IST)**. Specification: [MILESTONES.md](../MILESTONES.md), supplemented by the later issue acceptance criteria. This is an acceptance audit, not a claim that every milestone is complete. **All eight milestones still have gaps against the original specification.** Working source, a passing mock test, and a successful production workflow are different evidence.

## Expected versus actual — all eight milestones

This summary describes the **verified Pages/Worker release** and calls out differences in the retained Python implementation below. **Partial does not mean unusable:** a controlled production workflow passed, but it does mean the complete original milestone cannot honestly be marked done.

**What “portal support” means:** finding a URL in search, verifying a public JD, scraping a portal's board, and submitting its application are four separate capabilities. None of the following sites has been certified by submitting a real employer application during QA.

**Latest matrix evidence:** `/tmp/hireflow-multisite-production-proof/proof.json`, actual Pages UI using a temporary owner session for the existing workspace. Five search calls completed in **10.834 seconds**; eight verified listings produced **four new imports and four already-known results**. All five source rows rendered; the page showed nine saved listing cards, nine “View listing” links and labels from three sites. At 390 px there was no horizontal overflow; there were zero JS errors. Existing opportunities were retained, the temporary session was revoked, and **no application was submitted**. Candidate counts are search results, not a promise that every candidate was fetched or accepted. Verified per-source counts include already-known listings; they are not per-source new-import counts.

The released source-aware discovery replaces the earlier two mixed-domain searches. Internship mode has five sources (Internshala, Wellfound, Greenhouse, Lever, LinkedIn); Job mode has four (Naukri, LinkedIn, Greenhouse, Lever). Queries run concurrently; source-host filtering, round-robin verification and a shared cap of eight verified results keep the request bounded. The **five-source Internship path is production-UI verified above**. The four-source Job path has local regression coverage, not an equivalent cited live Job-mode run. Neither this release nor its counts add login/application automation or establish a 100+ cycle. Current discovery release: **Worker `4c80c9ad-1460-424d-bf06-25705f0e7d9f`, Pages `fa07b297`**.

Two implementations now coexist:

- **Python/Docker:** FastAPI, SQLAlchemy/PostgreSQL, local Playwright, ReportLab, optional sentence-transformers/FAISS. This remains the original implementation under `src/`.
- **Cloudflare:** TypeScript Worker, D1, private KV files with an optional R2 adapter, Queues, and Browser Run under `cloudflare/`. The React dashboard shares its API contract. This is an intentional deployment adaptation; it does not run Python, PostgreSQL, or FAISS on Workers.

The frontend is deployed at **https://hireflow-dashboard.pages.dev**, with the API at **https://hireflow-api.baidpankaj567.workers.dev**. Pages forwards private `/api/*` requests through its `API` service binding. Vercel remains a temporary old-cookie migration bridge. D1 migrations 0001–0003 are applied. Deployment and a completed browser workflow are separate verification gates; see the evidence below.

## Status definitions

| Status | Meaning |
|---|---|
| Implemented | The stated behavior exists in the named implementation and has relevant local tests. This does not imply every portal or a production delivery has been tested. |
| Partial | Some required behavior exists, but an acceptance condition, normal-path integration, or substantive coverage is missing. |
| Missing | The reviewed normal execution path does not implement the requirement. |
| Unverified | Code or configuration exists, but the relevant real integration or deployment has not been proved. |
